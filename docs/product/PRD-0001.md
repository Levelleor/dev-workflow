# PRD-0001: dev-workflow

## Problem

Developers need a portable, cost-conscious coding-agent harness that works with new and existing repositories, preserves task and architectural context, and verifies implementations instead of trusting a model's completion claim.

## Intended capabilities

- Bootstrap a repository with minimal conventions and a discoverable knowledge base.
- Expose model/role settings, thinking levels, budgets, retries and workflow limits.
- Delegate bounded implementation to inexpensive workers and use stronger reasoning selectively.
- Enforce deterministic verification and independent review before acceptance.
- Recover interrupted work and later support isolated parallel writers with serial integration.
- Package the CLI independently for npm while allowing dev-workflow to use the same conventions against itself.

## Accepted future direction (2026-11-26)

Pi remains the primary conversational cockpit and workflow dashboard. A dedicated extension manages agents through the Pi SDK, with independent configuration, native control tools, ongoing chat, monitoring and human intervention. Preserve agentctl as the knowledge/data CLI with a modular backend boundary and the existing sequential default; later parallel agents require shared persistence outside the repository. Every feature is vetted sequentially even when features run concurrently; human validation before integration to main is mandatory. Prioritise portability, reliability and reduced expensive-model usage. See [ADR-0004](../decisions/ADR-0004-pi-sdk-extension.md), [ADR-0005](../decisions/ADR-0005-agentctl-backend-adapters.md), [ADR-0006](../decisions/ADR-0006-feature-quality-and-human-gates.md) and [brainstorming](../knowledge/brainstorming/BRAINSTORM-0001-pi-native-development-harness.md). Workflow format, storage technology and precise approval surface remain open.

## First milestone

Establish monorepo structure, role and record templates, self-hosted project configuration, and an initial TypeScript CLI with deterministic setup/record operations and unit tests. Autonomous agent execution is a subsequent milestone.

## Non-goals for the first milestone

No live agent execution, Ultracode invocation, npm publish, runtime database, CI quality gates for generated products or automatic migration of existing repositories.

## Open design questions

Final npm package name and licence; record schema and CLI command semantics; trusted verification implementation; Ultracode integration mechanism; runtime persistence backend; exact model/provider support.
